# Skill: maintain-claude-md

## Why this exists

Claude Code auto-loads `CLAUDE.md` from the current directory and its ancestors on
every session, with zero extra plumbing — the single most leveraged, zero-cost
context mechanism it has. Skailr previously wrote exactly one `CLAUDE.md`, at
project root, and it held only Skailr's own intake-routing prose. Everything Skailr
learned about *this specific project* — stack, directory boundaries, house
conventions — went into `.claude/repo/orientation.md`, a Skailr-proprietary format
nothing outside an explicitly-dispatched researcher ever reads. This skill closes
that gap: it puts the project's own knowledge where the model already looks,
automatically, at every level, in both Skailr and vanilla Claude Code sessions.

## Root CLAUDE.md: two zones, two owners

Root `CLAUDE.md` is delimited into two independently-owned HTML-comment-bounded
zones. Never write outside your own zone; never assume the other zone's content or
absence.

```
<!-- skailr:intake:start -->
...Skailr's own plain-chat intake routing prose, generated by scripts/remirror.sh
from .claude/intake.md, copied verbatim by install.sh/install.ps1 on every
install and upgrade...
<!-- skailr:intake:end -->

<!-- skailr:conventions:start -->
...project-owned content this skill writes and maintains...
<!-- skailr:conventions:end -->
```

**Ownership boundary.** The intake zone belongs to `scripts/remirror.sh` /
`install.sh` / `install.ps1` — this skill never reads or writes it, and the
installer's merge logic never touches anything outside it (see those files' own
comments for the mechanism). The conventions zone belongs to this skill —
`/map-repo` and `program-documenter` are its only writers. This split is what lets
Skailr keep the intake block in sync on every upgrade (as it always has) without
destroying accumulated project knowledge the way a blind file overwrite would.

## Nested CLAUDE.md files

For each `Directory Boundaries` row in `orientation.md` that names a **real,
separately-conventioned subtree** — has its own build/package config, or has ≥2
`House Conventions` rows scoped under its path — write `<path>/CLAUDE.md`. Skip
boundaries with nothing distinct to say beyond the root summary (a thin `Config` or
`Shared types` folder rarely earns its own file; `Backend`/`Frontend`/`Data`
usually do). These files are entirely project-owned; there is no Skailr zone inside
them, but wrap the generated content in the same `skailr:boundary:start`/`:end`
markers anyway — a human may append their own notes below the block later, and the
markers are what let a future reconcile touch only the generated part.

```
<!-- skailr:boundary:start -->
# <Boundary name> conventions
_Maintained by Skailr from .claude/repo/orientation.md — see the root CLAUDE.md
too. Edits inside this block may be overwritten by /map-repo or
program-documenter; edit orientation.md (or ask for a remap) instead. Notes
outside this block are yours and are never touched._

**Stack:** <this boundary's slice of orientation.md's Stack, if it differs from root>

**Conventions:**
<House Conventions rows whose path falls under this boundary — topic, path, excerpt>

**Testing:** <this boundary's testing convention, if orientation.md documented one>
<!-- skailr:boundary:end -->
```

## Baseline mode (called from `/map-repo`, after `orientation.md`'s quality gate)

Run directly by the orchestrator — this is a mechanical derivation from an
artifact already produced this run, not new discovery, so it does not warrant
another subagent dispatch (fit-test's own spawn-floor logic: a task this size
inlines).

1. Read `.claude/repo/orientation.md`.
2. **Root conventions zone.** If root `CLAUDE.md` doesn't exist, there is nothing
   to do yet for the intake zone (that's `install.sh`'s job on next install) —
   create the file with just the conventions zone; the intake zone arrives
   whenever Skailr is (re)installed into this project. If it exists without a
   `skailr:conventions:start` marker, insert an empty conventions zone
   immediately after the intake zone (or at end of file if no intake zone
   exists either — a bare, non-Skailr-installed project). Then write, inside the
   conventions zone:
   - One-line Stack summary.
   - Directory Boundaries table, same rows as `orientation.md`, with a fourth
     column linking to each boundary's own `CLAUDE.md` where one was written
     (`see path/CLAUDE.md`) or `—` where none was.
   - Up to ~5 House Conventions rows that are genuinely repo-wide (don't cleanly
     scope to one boundary) — not a copy of the whole table; the rest live in
     their boundary's own file.
3. **Boundary files.** For each qualifying boundary (see above), write or
   overwrite `<path>/CLAUDE.md` in full (these are net-new, wholly-generated
   files on a first run).
4. Report every path written/updated back to the caller (`/map-repo`'s final
   report already lists new artifacts — include these).

Idempotent: re-running (a remap) regenerates both zones from the current
`orientation.md`, same as `orientation.md` itself gets regenerated on remap.

## Reconcile mode (called from `program-documenter`)

Only runs if `.claude/repo/orientation.md` exists — this skill never performs a
fresh researcher-style mapping pass itself; that is `/map-repo`'s job alone. If it
doesn't exist, skip with a one-line note (`claude-md: no orientation.md, skipped`)
in the caller's report and stop.

1. Read the diff. Determine whether it: (a) added or removed a top-level directory
   that orientation.md's Directory Boundaries doesn't yet reflect, or (b) changed
   a convention that a root or boundary `CLAUDE.md` currently documents (same
   "grep the docs tree for references to the changed surfaces" method
   `program-documenter` already uses for its other reconcile work).
2. For each hit, update **only** the affected rows/lines inside the relevant
   `skailr:conventions` or `skailr:boundary` block — surgically, same rule as
   every other reconcile-mode doc: do not restructure, do not re-derive the whole
   file, do not touch content outside your own zone.
3. A new directory boundary big enough to matter but not yet reflected in
   `orientation.md` itself is a gap in the baseline, not something to silently
   patch around — note it in the caller's Gaps and Follow-ups instead of
   inventing boundary content from the diff alone. Reconcile mode updates what
   orientation.md already established; it does not re-run `/map-repo`.

## What this skill never does

- Never writes application code, tests, or config — CLAUDE.md files only.
- Never touches the intake zone of root `CLAUDE.md` — that is
  `install.sh`/`install.ps1`/`remirror.sh`'s exclusive territory.
- Never invents a boundary or convention `orientation.md` doesn't support. If the
  map is stale, the fix is a remap, not a guess.
